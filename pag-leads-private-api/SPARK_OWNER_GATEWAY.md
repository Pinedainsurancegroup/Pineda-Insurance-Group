# PAG Leads v1.8 — ruta Spark para Reclutamiento (preparada)

La nueva pasarela `SparkOwnerGateway.gs` vive en un proyecto **Apps Script separado**, propiedad de Juan. No reemplaza el Apps Script actual ni modifica la hoja/formulario. El proyecto Firebase permanece en Spark; no se activa Blaze. La función de Cloud Functions preparada anteriormente queda sin publicar.

1. Crear el proyecto separado desde la cuenta que tiene acceso a la hoja privada. Pegar únicamente el archivo `SparkOwnerGateway.gs` del repositorio. En **Propiedades del script**, establecer `OWNER_UID` con el UID Firebase verificado de Juan, `SPREADSHEET_ID` con el ID privado de la hoja vigente y `SHEET_NAME` con el nombre de la pestaña vigente. Nunca publicar aquí el ID privado ni un token.
2. Autorizar en la cuenta de Juan el acceso a Sheets y las solicitudes HTTPS. Implementar como **aplicación web, ejecutar como yo (Juan), acceso cualquier usuario** para que la app pueda presentar su token Firebase mediante POST. La URL sola no da acceso: cada solicitud consulta `/users/{ownerUid}` con el token Firebase y las reglas Firestore; solo `role=owner`, `active=true`, `suspended!=true` recibe datos. Respuestas `ok:false` no incluyen registros.
3. Desde un entorno privado probar `ping`/`list` con sesión owner y comprobar rechazo de token ausente, agente y owner suspendido. Probar límites de volumen y campos contra la hoja real. No suspender el owner de producción solo para una prueba sin prever recuperación administrativa.
4. Solo después de probar la pasarela, colocar su URL HTTPS de despliegue en el recurso Android `pag_owner_gateway_url` y compilar **QA separada**. Verificar navegación, cantidad y contenido de Reclutamiento en el teléfono antes de proceder a sincronización. No colocar el token heredado en la APK.

El token Firebase viaja por HTTPS en el POST nativo; no se entrega a JavaScript ni sigue las redirecciones de respuesta. El Android solo acepta URL de `script.google.com/macros/s/.../exec` y respuesta redirigida al dominio de contenido Google. La pasarela usa un URL público para permitir POST desde Android, por lo que una avalancha de solicitudes puede consumir la cuota de Apps Script aunque no lea la hoja. Mantener límites y seguimiento de cuotas; al agotarse, Apps Script detiene ejecuciones hasta la renovación de cuota, sin crear automáticamente un cargo por consumo. La pasarela no reemplaza el control de acceso del endpoint antiguo aún activo ni recupera estados/notas locales: ambas migraciones siguen pendientes.
